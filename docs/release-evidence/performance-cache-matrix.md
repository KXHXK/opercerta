# OperCerta 缓存与工具模式矩阵证据

## 测量目的

本矩阵只验证 Redis 是否按设计减少重复只读取证的 MCP 调用，以及并行/串行工具模式都能完成三个 query 场景。它不是容量测试、生产压测、SLA 或并行性能优势证明。

## 固定方法

2026-07-20 在 WSL2 Ubuntu 26.04 LTS、Docker Engine 29.1.3、Compose 2.40.3 上运行：

```bash
bash scripts/run_performance_matrix.sh tmp/performance-task7-final
```

- 维度：缓存关闭/开启 × 工具并行/串行。
- 每格：库存、设备、作业各 5 次 query，共 15 次；12 个场景单元共 60 次。
- 每个模式重建当前工作树镜像；每格开始前清空 Redis。
- query 只做取证、确定性评估和报告，不调用模型，也不创建审批或工单。
- 报告从逐次实际请求生成，不手填 aggregate。

## 观察结果

- 60/60 个 operation 终态为 `completed`，错误数为 0。
- 模型调用数和 token 数均为 0，符合 query 契约。
- 关闭缓存时，每个场景 5 次 query 产生 10 次 MCP 读取、0 次 cache hit。
- 开启缓存时，每个场景首次 query 的两份证据来自 MCP，随后四次各命中两份证据，因此为 2 次 MCP、8 次 cache hit。

## 可证明与不可证明

可证明：固定 TTL 和固定合成证据下，缓存路径确实命中，并把每场景重复取证的 MCP 调用从 10 次降为 2 次；缓存关闭时仍全部完成。

不可证明：每格只有 5 次、本机容器调度噪声较大，因此 P50/P95 不支持生产容量、成本、SLA 或“并行一定快于串行”的结论。批准后的 revalidate 始终绕过 Redis，本矩阵不改变安全写入路径。
