# OperCerta 库存补货固定契约回归评测设计

**状态：** 已确认，尚未实施  
**日期：** 2026-07-18  
**范围：** 当前已实现的库存补货后端、合成数据、FastAPI、MCP、PostgreSQL、JWT/RBAC 与恢复边界。  
**非范围：** 设备场景、真实模型、模型准确率/成本/时延、前端、SSE、SSO、公开部署和生产业务效果。

## 1. 目标与诚实边界

建立冻结、可重复运行的 30 条合成契约回归用例。它只证明当前 OperCerta 对已声明的 API、状态机、权限和数据库后置条件没有退化；不证明 Agent 的通用智能、真实模型质量、生产效果或独立第三方评测结论。

每条用例必须绑定到已有设计规则、稳定错误码、角色权限或状态转换，运行报告保留全部逐例结果和失败原因。发布门禁保持 `CLOSED`，不能用评测通过替代公开发布门禁。

## 2. 反偏差规则

1. 用例数据集 `data/evals/replenishment-v1.json` 在首次通过前即纳入 Git；其 `suite_version` 固定为 `replenishment-v1`。
2. 运行器只能读取用例中声明的请求、身份、预期 HTTP 码、终态、审批/工单数量和审计事件；不能读取生产实现的私有状态来决定预期。
3. 每个用例记录 `rule_refs`，指向已有规格、错误码或状态机语义；缺少引用的用例不允许进入套件。
4. 失败时生成完整 JSON 报告，不允许只输出通过率、跳过失败或自动改写期望值。
5. 修改冻结用例的期望或移除用例必须提高 `suite_version`，在开发日志解释原因，并重新执行全套；报告必须显示版本变化。
6. 评测报告只写实测的通过/失败计数和运行时间，不把它们表述为准确率、SLA、业务指标或模型能力。

## 3. 30 条用例分布

| 分组 | 数量 | 已实现契约 |
| --- | ---: | --- |
| 正常业务与只读 | 5 | 低库存创建、正常库存零工单、查询、未知库存安全失败 |
| 输入与请求契约 | 4 | 空消息、额外字段、错误动作/对象、缺失必填字段 |
| JWT 与角色权限 | 7 | 缺失/篡改/过期/错误签发方或受众、operator、approver、auditor 的边界 |
| 审批绑定与终态 | 6 | 批准、拒绝、过期、绑定失配、重复审批、审批主体可信注入 |
| 写入与恢复 | 5 | 单工单、幂等重放、审批后事实变化、写后读、重启恢复 |
| 安全回归 | 3 | `approver_id` 伪造、未知工具、受控参数/规则拒绝 |

用例只使用 `SKU-LOW-001`、正常库存 SKU 与缺失 SKU 等已有合成种子；不得引入真实公司、客户、库存或设备数据。

## 4. 数据、运行器与报告契约

每条 JSON 用例至少含：

- `id`：稳定、唯一的 `RPL-001` 至 `RPL-030`；
- `title`：中文短标题；
- `rule_refs`：至少一条已存在规则引用；
- `actor`：`anonymous`、`operator`、`approver`、`auditor` 或 `demo-admin`；
- `steps`：允许的 API 请求和可选的重启/恢复动作；
- `expected`：HTTP 码、终态、稳定错误码、审批数、工单数与关键审计事件。

运行器为独立 Python 命令，使用现有集成测试的真实 PostgreSQL、FastMCP 和 FastAPI 夹具语义。每条用例使用独立 operation 和 cleanup；它不能依赖测试库干净这一隐含前提，也不能把其他 operation 的全局恢复结果误判为当前用例失败。

报告写入被忽略的 `tmp/evals/`，输出 JSON，至少包含：`suite_version`、UTC 开始/结束时间、运行环境说明、用例总数、通过数、失败数、逐例 `id/status/duration_ms/failure_summary`。不得写入 JWT、密码、数据库 URL、请求 Authorization header、MCP 内部异常或隐藏推理。

## 5. 门禁与验收

- 数据集 schema 和引用完整性必须有单元测试；
- 至少一条故意不匹配的临时测试输入证明运行器会报告失败，而非忽略；
- 30 条真实用例全部通过，报告 `failed=0`，才可记录“本地契约评测基线通过”；
- 任一失败、缺失报告或泄露敏感信息均保持发布门禁关闭；
- 全量 pytest、Ruff、格式检查、mypy 和 WSL2 Compose smoke 必须继续通过。

## 6. 限制

本套件是项目作者维护的白盒回归基线，不能替代独立第三方隐藏集、红队评估、渗透测试、真实模型评测或生产监控。面试和简历只能表述为“为 OperCerta 已实现契约建立了 30 条固定合成回归评测”，并同时说明上述限制。
