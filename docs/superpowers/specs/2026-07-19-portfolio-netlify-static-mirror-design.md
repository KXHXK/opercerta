# 作品集 Netlify 静态镜像设计

**状态：** 已确认，待用户审阅书面规格后编写实施计划
**日期：** 2026-07-19
**适用范围：** OperCerta 作品集入口的公开静态镜像
**不改变：** OperCerta 产品发布门禁仍为 `CLOSED`

## 1. 背景与目标

现有个人作品集由 `D:\CODEX\resume\portfolio` 中的 Vinext/Sites 项目生成，内容已在本地构建与 SSR HTML 检查中确认包含 OperCerta 专题入口。但其 Sites 公网地址在当前网络返回 Cloudflare `403`，不满足 HR 或面试官无需登录即可访问的目标。

OperCerta 静态专题 `https://opercerta-kxh.netlify.app` 已独立生产部署并可访问，但它只展示合成数据证据，不提供 API、数据库、MCP 或公开写入。本设计只解决“个人作品集可公开访问并跳转至 OperCerta 专题”的入口问题；不把静态站点表述为 OperCerta 交互式生产上线。

目标是构建一个零后端、无冷启动、可由 Netlify 公开托管的作品集静态镜像，使访问者能快速看到当前作品集视觉设计，并从 OperCerta 卡片跳转到已验证的静态专题。

## 2. 方案比较与决定

### 方案 A：从现有 Vinext 构建产物导出静态镜像（采用）

在独立镜像目录中调用现有作品集的生产构建，使用已构建的服务端入口渲染首页 HTML，复制客户端资源，输出纯静态目录并由 Netlify 发布。

- 优点：复用现有页面和样式，避免维护第二套 React 页面；无服务端函数、无数据库、无冷启动；发布物可做确定性检查。
- 代价：源作品集改动后需要重新导出并部署；首次实现需要明确 SSR 产物、资源路径和失败语义。

### 方案 B：重写一套 Vite/React 作品集

- 优点：构建模型直接、完全独立。
- 缺点：复制页面、样式和内容，后续会出现两套源码漂移；不采用。

### 方案 C：在 Netlify 上运行 SSR/Functions

- 优点：接近当前 Sites 的 SSR 结构。
- 缺点：引入 Functions、冷启动和运行时配置，超出“HR 快速静态访问”的需求；不采用。

决定采用方案 A。

## 3. 架构与边界

```text
作品集源码（Vinext/Sites，保持现状）
  -> 生产构建
  -> 服务端渲染首页 HTML + 复制客户端资源
  -> 独立静态镜像输出目录
  -> 独立 Netlify 站点
  -> 访问者点击 OperCerta 卡片
  -> https://opercerta-kxh.netlify.app
```

### 3.1 源码边界

- `D:\CODEX\resume\portfolio` 仍是作品集的唯一人工维护源码，并保留 `.openai/hosting.json` 与既有 Sites 部署。
- 新镜像工作目录放在 `D:\CODEX\resume\portfolio-netlify`，不包含 `.openai/hosting.json`，只承担静态导出、验证与 Netlify 发布。
- 镜像目录不复制或改写 OperCerta 后端、数据库、MCP、Docker Compose、凭据或旧公司材料。
- 现有 `opercerta-kxh` Netlify 站点不得覆盖；作品集使用独立站点名称与独立部署记录。

### 3.2 静态导出契约

导出器必须：

1. 成功执行现有作品集生产构建；
2. 用构建后的服务端入口渲染根路径 `/`；
3. 将客户端构建产物复制到镜像发布目录；
4. 写入 `index.html`，保留与复制资源一致的绝对 `/assets/...` 路径；
5. 验证 HTML 含作品集标题、OperCerta 名称、精确 URL `https://opercerta-kxh.netlify.app`、`target="_blank"` 与 `rel="noreferrer"`；
6. 验证 HTML 引用的本地 CSS/JS 资源真实存在；
7. 任一步失败即以非零退出，不生成“占位成功”页面。

### 3.3 运行时边界

- Netlify 只提供静态文件与 HTTPS，不接收业务写请求。
- 站点不保存表单数据、账号、访问者数据、token 或数据库连接串。
- 如 OperCerta 专题不可达，作品集链接仍为普通外链；不伪造在线业务可用状态。
- 作品集镜像出现故障时，可立即将简历链接指回已验证的 OperCerta 专题；现有 Sites 版本也保留为回退证据，但不作为当前网络的公开访问承诺。

## 4. 实施范围

### 包含

- 一个确定性的静态导出脚本与自动化测试；
- 输出目录、Netlify 发布配置和本地验证命令；
- 独立 Netlify 站点的预览与生产发布；
- HTTPS、标题、关键链接、资源状态和浏览器可达性核验；
- 将 Sites `403` 诊断、Netlify 解决过程和最终 URL 追加到 OperCerta 中文开发日志、当前状态、面试案例册与文档索引。

### 不包含

- OperCerta 公开 API、数据库、MCP、审批写入或交互式云演示；
- GitHub 仓库公开化、真实模型、设备场景、SSO/IAM、自动部署、浏览器 E2E 或产品发布门禁关闭；
- 对现有 Sites 项目、其用户既有脏修改或部署历史的清理、覆盖或重写。

## 5. 测试与发布门禁

按 TDD 执行：先写导出失败用例，再实现导出器。

| 门禁 | 通过条件 |
| --- | --- |
| 导出契约 | 缺少服务端入口、渲染非 200/非 HTML、缺少 OperCerta 精确 URL、缺少资源任一情况均失败 |
| 构建 | 源作品集生产构建成功，静态目录包含 `index.html` 和其引用的资源 |
| HTML | 标题、OperCerta 卡片、外链安全属性与移动菜单内容均存在 |
| 部署 | Netlify preview 与 production 均成功，且不覆盖 `opercerta-kxh` |
| 公网 | HTTPS 返回 200，页面标题正确，OperCerta 链接可解析；必要时在浏览器复核 |
| 诚实边界 | 页面不新增 API 地址、演示账号、性能承诺或“已完整上线”声明 |

## 6. 风险与处理

| 风险 | 处理 |
| --- | --- |
| 源作品集工作树含用户脏修改 | 仅读取并构建；镜像工程与 OperCerta 文档在独立工作树提交，不暂存无关修改 |
| Vinext 构建变更资源路径 | 导出测试直接解析 HTML 并校验每个本地资源存在 |
| Netlify 登录或网络失败 | 保留可复现的本地发布目录和手动 CLI 步骤；记录实际错误，不伪造上线 |
| Sites 403 再现 | 记录为平台访问层问题；不把其解释为源码或 Netlify 故障 |
| 误把静态入口称为业务系统 | README、专题和日志持续标注“静态展示，不提供公开写入” |

## 7. 验收后的交接

完成后必须记录：独立 Netlify 站点 URL、部署 ID 或等价版本证据、发布提交、HTTPS 验证时间、OperCerta 链接验证结果、回退方式以及仍未完成的公开交互后端范围。只有这些事实写入后，才可把作品集“入口可公开访问”标记为完成；OperCerta 产品 release gate 仍保持 `CLOSED`。
