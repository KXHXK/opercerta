## 问题一：非交互 WSL 登录 shell 找不到 Node

### 现象

交互式 Ubuntu 终端可以执行 Node，但由 Windows 调用 `wsl ... bash -lc` 时找不到 Node。环境门禁因此可能在人工终端通过、在自动化命令中失败。

### 根因

Node PATH 只写入 `.bashrc`。Ubuntu 的 `.bashrc` 对非交互 shell 会提前返回，而登录 shell 应从 `.profile` 获取持久 PATH。

### TDD 修复

1. 先在 `tests/unit/runtime/test_wsl_bootstrap_assets.py` 增加契约，要求引导脚本同时维护 `.bashrc` 和 `.profile`。
2. RED 阶段确认 `.profile` 断言失败。
3. 修改 `scripts/bootstrap_wsl_environment.sh`，以幂等循环把同一固定 PATH 写入两个 profile。
4. 在真实用户环境补齐 `.profile` 后，`bash -lc` 可直接读取 Node、npm 和 uv。
5. GREEN 阶段定向测试 `7 passed`。

该修复不修改系统 Python、不使用 root 安装 Node，也不把本机绝对路径硬编码到仓库。

## 问题二：冻结 Python 依赖冷同步过慢

### 现象与诊断

`uv sync --frozen --all-groups` 在新机空虚拟环境中长期停留在官方下载。网络探针表明清华 PyPI 镜像响应明显更快；同时 `uv.lock` 内含精确官方制品 URL，仅设置默认 index 不能改写这些已锁定 URL。

### 本机恢复方式

- 从 `uv.lock` 冻结导出带 hash 的临时 requirements，不改写锁文件。
- 使用清华 PyPI 镜像和 `--require-hashes` 同步 109 个已锁定依赖，再以 `--no-deps --editable .` 安装当前项目。
- 全过程保持版本和 hash 校验，临时清单只存放于已忽略的 `tmp/`，不是新的依赖来源基线。

这是本机恢复策略，不等于 Docker 空缓存冷构建已经优化完成。Dockerfile 和 Compose 未因本次网络实验扩大改造范围。

## 问题三：DrvFS chmod 不持久化

仓库位于 `/mnt/d`。权限探针显示文件创建后为 `777`，`chmod 755` 返回成功但 mode bits 不变化，挂载参数也未启用 `metadata`。当前前后端测试、构建和 Compose 均未被阻断，因此继续把它记录为已知跨平台约束，不在本轮修改 `/etc/wsl.conf`。秘密文件依靠 Windows ACL、Git ignore 和仓库安全扫描共同保护；不能把 chmod 成功作为唯一安全证据。
