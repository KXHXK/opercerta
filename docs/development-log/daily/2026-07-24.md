## TDD 修复

### 未知后端错误不得向用户暴露原始消息

- **RED：** 新增客户端测试，构造未映射错误码和包含 provider/traceback 细节的安全 envelope，证明旧 `ApiError` 会把后端 `message` 直接放入 `Error.message` 与界面提示。
- **根因：** 客户端虽然只解析 `code + message` envelope，但未知 `code` 的 fallback 仍拼接原始 `message`，与“未知响应固定兜底、不显示原文”的规格冲突。
- **GREEN：** `ApiError` 只根据 allowlist 错误码生成可执行中文提示；未知错误统一为固定安全文案和 HTTP 状态，不再使用后端正文。
- **证据：** 聚焦客户端/App/审批组件测试 `17 passed`；前端全量随后 `53 passed`。

### 审批已写入后，读取终态失败不能显示“审批未提交”

- **RED：** 新增 App 编排测试：审批 API 返回 204，但审批后详情刷新因角色权限返回 403；旧实现把刷新异常继续抛给审批组件，界面误报“审批未提交”并允许重复点击。
- **根因：** “提交审批”与“读取最新状态”被当作一个全成全败操作，混淆了写入事实和后置读取结果。
- **GREEN：** 只让审批写入失败拒绝回调；写入成功后的刷新失败被单独捕获，页面明确显示“审批已提交，但未能读取最新处置”，审批按钮保持禁用，并引导切换 auditor 或稍后读取。
- **意义：** 避免用户在数据库已经完成原子决定后重复提交，也与最小权限 RBAC 的角色接力一致。
