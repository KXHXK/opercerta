# AI Agent 四项目命名设计规格

> 状态：命名方案已于 2026-07-14 经用户确认；本文档等待书面复核，尚未执行任何仓库、目录或文档重命名。

## 1. 目的

为四个面向 AI Agent／大模型应用开发岗位的作品项目建立可长期使用、便于面试解释且降低同名冲突风险的独立品牌名，同时保留中文功能副标题，确保招聘方无需猜测项目用途。

本文档只冻结命名、展示规则、冲突检索结论及后续迁移边界，不改变已经通过的业务闭环、系统架构、技术栈、实施顺序、效果指标口径和上线计划。

## 2. 设计目标与约束

1. 品牌名应具备一定独创性，避免继续使用网上已有较多同名项目或产品的通用组合词。
2. 名称应能从项目业务逻辑中自然解释，面试时不依赖生硬的营销故事。
3. 四个项目采用彼此独立的英文品牌，但在简历、作品集和 GitHub 中统一使用“英文品牌｜中文功能副标题”的展示格式。
4. 中文副标题负责说明业务价值，英文品牌不承担罗列框架、模型或数据库的职责。
5. 名称不能反向驱动技术堆砌，也不能改变项目原有的企业级闭环设计。
6. 仓库 slug 使用全小写单词，不使用空格、下划线或额外后缀。

## 3. 已比较的命名策略

### 3.1 直接描述型组合词

用 Flow、Agent、Security、Field、Federated 等通用词直接拼接。优点是容易理解，缺点是搜索结果拥挤、同名概率高，也容易显得像教程项目。因此不采用。

### 3.2 完全虚构词

创造与业务无明显联系的短词。优点是更容易获得独特性，缺点是面试时解释成本高，招聘方首次看到时无法判断项目方向。因此不采用。

### 3.3 可解释的造词

从业务核心概念中各取一部分形成新词，再通过中文副标题消除理解门槛。它兼顾独特性、可读性和可解释性，是本次选定方案。

## 5. 标准命名解释与面试口径

### 5.1 OperCerta

OperCerta 由 Operations 与 Certainty 组合而来。项目的核心不是让大模型自由执行运维动作，而是把不确定的运营事件转化为有证据、有审批、有执行边界、可审计且可恢复的确定性处置流程，因此名称强调“运营处置的确定性”。

推荐面试回答：

> 我把项目命名为 OperCerta，是因为企业运营 Agent 的关键不只是能调用工具，而是把模型的不确定判断约束成可验证、可审批、可回滚的执行结果。名称对应的正是项目从事件理解到受控处置的完整闭环。

### 5.2 ForenTrail

ForenTrail 由 Forensic 与 Trail 组合而来。项目围绕“安全信号—证据归集—关联研判—人工处置—审计留痕”构建链路，强调结论必须能够沿证据轨迹回溯，而不是只输出一段缺少依据的告警摘要。

推荐面试回答：

> ForenTrail 强调 forensic evidence trail。安全研判不能只给风险标签，还要保留证据来源、推理依据、人工确认和后续处置记录，名称与系统的证据闭环和审计要求是一致的。

### 5.3 SiteVerum

SiteVerum 由 Site 与拉丁语 Verum（真实）组合而来。项目的现场判断必须由原始图像或视频、确定性视觉工具、检索到的规范资料和人工复核共同支撑，名称突出“以现场真实证据为准”。

推荐面试回答：

> SiteVerum 表达的是现场事实优先。多模态模型可以帮助理解图像和组织结论，但每条巡检结论都必须回到原始素材、工具结果和规范依据上，避免模型把看似合理的描述当成现场事实。

### 5.4 Federune

Federune 由 Federated 与 Run 组合而来。项目把每次联邦学习实验视为一个经过版本化配置、预检、审批、受控执行、指标评估和结果复现的 run，强调工程治理而非单次算法演示。

推荐面试回答：

> Federune 的重点不是再做一个联邦学习算法 Demo，而是把一次实验变成可配置、可验证、可审批、可追踪和可复现的工程运行单元，所以名称直接对应 federated run 这一核心抽象。

## 6. 统一展示规则

1. 项目页面主标题、简历项目标题和作品集卡片统一使用“英文品牌｜中文功能副标题”。
2. GitHub 仓库名及本地目录名分别使用 `opercerta`、`forentrail`、`siteverum`、`federune`。
3. README 首个一级标题使用完整展示名称；正文首次出现时可以补充标准命名解释，后续只使用英文品牌名。
4. 包名、Docker Compose 项目标识、监控 service name 和部署应用名以后统一从仓库 slug 派生，具体规则在各项目实施阶段确定。
5. 不在英文品牌中追加 AI、LLM、GPT、LangGraph、RAG、Milvus、Kafka 等技术词；技术能力由架构和项目内容体现。
6. OperCerta 中文副标题中的“Agent”用于明确岗位相关性；其余项目按真实产品形态使用“平台”，不强行统一后缀。

## 7. 名称冲突初筛记录

### 7.1 检索范围

在 2026-07-14 对四个最终名称进行了点时检索，范围包括：

- 通用网页精确名称检索及相近业务领域检索；
- GitHub 项目、PyPI 包和 npm 包的明显同名结果；
- 同类 AI、安全、视觉巡检和联邦学习产品的名称冲突；
- Verisign RDAP 对应 `.com` 域名的注册状态查询。

### 7.2 初筛结论

初筛未发现 OperCerta、ForenTrail、SiteVerum、Federune 在对应软件领域存在显著的同名产品、活跃开源项目或主流包名冲突。查询时 `opercerta.com`、`forentrail.com`、`siteverum.com`、`federune.com` 的 RDAP 返回未找到注册记录。

该结论只代表 2026-07-14 的公开信息初筛，不等同于商标法律意见，也不代表域名已被保留。正式商业化、注册商标或购买域名前，应重新进行实时域名、商标及企业名称核验。
